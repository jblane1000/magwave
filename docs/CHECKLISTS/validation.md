# Checklist — validation

Run before any release and on every change to an engine's numerics. A tick means a command was run and
its output was seen, not that the code looks right.

## Rung 1 — closed-form analytics
- [ ] Dipole: field at 10 points vs analytic, tolerance ≤ 1 %.
- [ ] Current loop on axis: field vs closed form, ≤ 1 %.
- [ ] Finite solenoid on axis: vs elliptic-integral solution, ≤ 1 % at 10 stations.
- [ ] Uniformly magnetized cuboid: field at 20 sample points vs closed form, ≤ 1 %.
- [ ] Uniformly magnetized cylinder: on-axis and off-axis samples, ≤ 2 %.
- [ ] Halbach array: on-axis field and uniformity figure vs analytic, ≤ 2 %.
- [ ] Two-magnet force: vs analytic/dipole outside near-contact, ≤ 2 %.

## Rung 2 — published benchmarks
- [ ] TEAM 20 (3D static force): case file present; reference value cited with source.
- [ ] Result within the scatter reported across published codes; deviation recorded, not hidden.
- [ ] Any benchmark where we disagree is listed in `docs/BENCHMARKS.md` with an explanation.

## Rung 3 — second code
- [ ] Same geometry run through an independent code (Elmer, or FEMM for the 2D case).
- [ ] Agreement stated as a number with a tolerance; "looks the same" is not acceptance.
- [ ] Disagreement resolved or documented as an open issue with a named owner.

## Rung 4 — measurement
- [ ] Hall-probe measurement of a real part recorded: probe model, calibration date, ambient temperature.
- [ ] Measured vs simulated table, with the uncertainty of the probe stated.
- [ ] Discrepancy > 10 % investigated before release.

## Harness hygiene
- [ ] Suite runs headless in CI; no display, no network (socket guard active).
- [ ] Every case declares source, expected value, tolerance, engine version.
- [ ] Perturbing any expected value by 1 % fails the suite (anti-vacuity check).
- [ ] `docs/BENCHMARKS.md` regenerated by CI and committed by the release workflow.
