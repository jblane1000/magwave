# ADR 0005 — The benchmark harness is the first deliverable

- Status: accepted
- Date: 2026-11-17

## Context

Field plots look plausible even when wrong. Force results are especially seductive: a wrong number with
the right order of magnitude has shipped bad hardware. The project's credibility rests on being provably
right on a declared subset — and the author's working rule is that an agent's or a program's own summary
is not evidence.

## Decision

1. The benchmark harness lands **before** the first feature (M1).
2. Every benchmark case declares: source of truth (closed-form | TEAM | second code | measurement),
   expected value, tolerance, and the engine version it was produced with.
3. `docs/BENCHMARKS.md` is generated by CI, never hand-edited (FR-071).
4. A feature without a benchmark case is not "done"; it is "unverified", and is labelled so in the README.
5. Non-convergence, dropped bodies and unmet capabilities are errors (NFR-8), never warnings that scroll.

## Consequences

- Slower feature cadence, much faster trust.
- Every quoted number in docs and chat can name its rung (analytics → TEAM → second code → measurement).
- The suite doubles as regression insurance when engines are swapped (ADR 0003).
